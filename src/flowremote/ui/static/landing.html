Why FlowRemote

Automation is fast.
Trust is the bottleneck.

A bot can move thousands of rows before anyone notices a bad one. FlowRemote puts the review, the evidence and the approval exactly where the risk is.

01 / accountability

The bot owns the work. Nobody owns the outcome.

Autonomy without a named approver turns one wrong field into a compliance incident — and no one can say who let it through.

02 / exceptions

Exceptions live in spreadsheets and chat.

Missing IDs, impossible dates and amount mismatches hide in row 4,812. Tracing them by hand is slow, repetitive and easy to get wrong.

03 / evidence

There is no story for the auditor.

If you cannot show who approved what, with which evidence and when, the workflow is not ready for production.

How it works

From workbook to signed-off batch in four steps.

One loop, designed around the exception rather than the happy path.

01

Upload the workbook

Start with an .xlsx order file. Headers, row count and every required field are validated before a task is created.

orders-v1 · up to 10,000 rows
02

Rules find the exceptions

One exception per order, all reasons together, with the original Excel row, values and rule version kept intact.

deterministic validation
03

AI proposes. You decide.

Grounded suggestions show confidence, explanation and evidence. Accept, edit or skip — nothing is applied automatically.

human review
04

Approve, then watch it run

The gate opens only at zero unresolved. Approve once, follow each write in real time, keep the audit export.

single-use approval

What is inside

Built for the moment the AI is not sure.

The guardrails are the product, not a settings page.

Evidence, or no suggestion

The offline provider recovers a value only from an exact registry match or quantity × unit price. Invented customers, partial corrections and anything under 70% confidence are rejected before they reach the screen.

An approval gate that cannot be skipped

Unresolved exceptions block approval. Approving writes exactly one approval, opens one execution run, and cannot be replayed.

Every exception, fully explained

Original values, flagged fields, Excel row number, rule version and confidence stay attached to the decision — even after it is corrected.

Roles that match responsibility

Operators see the tasks they own. Admins see the workspace. Uploaded source files stay visible to owners and admins only.

Progress you can watch from a phone

Execution advances in steps of 20 records with written and synced counts kept equal. A partial write stops honestly instead of reporting success.

Audit-ready by default

Every decision, approval and execution event is appended to an activity log that exports as JSON for review.

Questions

What you should know before you click.

Is this a finished commercial RPA product?

No. FlowRemote is an ENT207TC coursework prototype built by a student team. The review, approval and audit workflows are implemented end to end, but the outward OA and BI writes are simulated. Nothing is sent to a real enterprise system.

Does the AI approve or execute anything?

Never. AI suggestions are advisory and validated before they are shown. A person accepts, edits or skips each exception, and a separate human action opens the approval gate and starts execution.

Which systems does it connect to?

Excel order workbooks work end to end today, including header mapping in English and Chinese. The OA and BI targets are simulated connectors behind a replaceable interface, and the database can run on SQLite locally or PostgreSQL for an enterprise deployment.

Can I run it locally?

Yes. The project uses Python, uv and FastAPI. Run uv sync, seed the demonstration data, then start uvicorn on port 8000. Local SQLite state survives restarts, and the README documents the full setup, seeding and test commands.

What happens to the data I upload?

The demo stores everything locally: SQLite for task state and data/runtime/uploads/ for the original workbook. There are no outbound calls unless you configure your own OpenAI-compatible key for live suggestions; the default provider runs offline.

Where is the source and the evidence?

The project repository contains the README, the PRD, the state-machine specification, weekly reports and the AI-use log required by the course. The application itself links the review and approval state directly to the seeded records, so every claim on this page can be checked in the demo.
